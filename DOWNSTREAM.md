# Rainny downstream contract

Rainny is a personal downstream distribution of [OpenCode](https://github.com/anomalyco/opencode).
The upstream project is MIT licensed. Keep `LICENSE`, upstream copyright notices, dependency notices, and
historical attribution intact.

## Repository contract

| Role | Value |
| --- | --- |
| Upstream | `https://github.com/anomalyco/opencode.git` |
| Upstream branch | `dev` |
| Downstream | `https://github.com/xiay8874-source/Rainny.git` |
| Integration branch | `dev` |
| Current customization branch | `rainny-branding` |

Sync upstream changes with:

```bash
git fetch upstream --tags
git switch dev
git branch backup/dev-before-upstream-sync
git merge --no-ff upstream/dev
```

Resolve conflicts by preserving upstream behavior first and then reapplying the Rainny identity at the
smallest integration seam. Do not replace every `opencode` occurrence globally.

## Identity manifest

| Surface | Rainny identity | Compatibility policy |
| --- | --- | --- |
| Product | `Rainny` (`Rainny Dev`, `Rainny Beta`) | Rename public UI and packaged metadata |
| Repository | `xiay8874-source/Rainny` | Keep `upstream` remote and source attribution |
| Desktop app IDs | `com.xiay8874.rainny.desktop[.dev|.beta]` | Do not reuse OpenCode application IDs |
| Deep link | `rainny://` | Accept `opencode://` only at a narrow migration boundary when required |
| Desktop artifacts | `rainny-desktop-${os}-${arch}.${ext}` | Do not publish assets under upstream names |
| Bundled CLI filename | `rainny-cli` | Internal OpenCode CLI protocol remains compatible initially |
| Desktop data root | Derived from the Rainny app ID | Import old OpenCode data without deleting it |
| Updater | `xiay8874-source/Rainny` | Disabled for dev builds; production reads Rainny-owned releases |
| Source packages | `@opencode-ai/*` | Preserve internally to avoid broad dependency churn |
| Environment variables | `OPENCODE_*` | Preserve as compatibility API until a versioned adapter exists |
| Config files | `opencode.json[c]`, `.opencode/` | Preserve so existing projects continue to work |
| Internal renderer protocol | `oc://` | Preserve; it is not a public OS protocol |
| OpenCode Zen/provider IDs | Upstream names | Preserve as third-party service identity |

## Downstream patch sets

1. `desktop identity`: branding constants plus thin packaging/runtime integrations.
2. `data migration`: copy compatible OpenCode settings into Rainny storage, never delete the source.
3. `CLI distribution`: expose a Rainny executable while retaining explicit OpenCode compatibility aliases.
4. `release`: Rainny-owned assets, checksums, updater metadata, signing, and rollback notes.

## Automatic updates

Rainny reuses the upstream Electron updater controller, renderer notifications, and install-and-restart flow. The
downstream integration changes only the release identity and keeps the update machinery at its existing seams:

- Production reads the `latest` channel from `xiay8874-source/Rainny`; beta reads the `beta` channel.
- Development builds keep updates disabled so unsigned local packages cannot replace themselves.
- The app checks on launch and every ten minutes, downloads one available update, persists the ready version, and
  offers install-and-restart through the existing menu and toast UI.
- Releases must include the matching `latest*.yml` metadata and signed platform artifact generated by
  `electron-builder`. A GitHub Release containing only a DMG is not sufficient for automatic replacement.
- macOS and Windows update artifacts must use a signing identity compatible with the installed build.

## Pending before public release

- Review the Rainny name and marks before public distribution; this document is not legal assurance.
- Configure macOS/Windows signing and notarization credentials.
- Verify clean-machine install, upgrade, rollback, and the signed updater flow.
- Publish a release only after the artifact and runtime verification ledger is complete.

Rainny `v1.18.10` is an Apple Silicon personal preview. Its macOS bundle is ad-hoc signed with the required
Electron entitlements, but it is not Developer ID signed or Apple-notarized. Gatekeeper therefore rejects the
bundle by default, and the signed automatic-update path remains unverified until release credentials are added.
